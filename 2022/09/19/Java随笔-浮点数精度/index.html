那，到底是什么原因导致了这种情况呢？

在 Google 一番并研究了好一阵子后，大概明白了一些。而且，似乎很多前辈们都曾在面试的时候折戟于这道看上去很 “简单” 的题目……

原理解释

首先，我们都知道，计算机是以二进制的形式进行存储的，数值也不例外。

Java 采用 IEEE 754 标准 来实现浮点数的表达、运算和存储。

以 0.1 而言，它的本质是 1/10，用二进制表示的话，就是 1/1010。然而问题就出现了——你会惊奇地发现，在二进制下，这个数是除不尽的，是一个无穷循环小数！

计算结果为：0.0001100110011001100110011…（0011 无限循环）

简单总结

1/10 无法用有限位数的二进制数进行表示，导致在 IEEE 754 标准下存储时存在数据截断问题，最终造成精度损失。

解决方法

同学们可能很疑惑：0.1 的精度损失也太小了吧，而且不会对计算产生很大影响。大不了下次比较的时候限制一下位数，四舍五入舍弃掉后面的误差值不就好了？

在我们平日简单的计算过程中，确实不必处心积虑地考虑这精度问题。但对于某些特别的场景，这种精度问题就必须要考虑了。

举个例子：如果我们大量使用 double 来进行金钱计算，只要数额够大，那 double 所损失的精度最终就会转换为白花花的 Money 💰
