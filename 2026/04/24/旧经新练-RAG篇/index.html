RAG（Retrieval-Augmented Generation）是把检索和生成结合起来：在 LLM 回答之前，先从外部知识库中检索相关文档作为上下文，再让模型结合这些信息生成答案。这一篇按”完整流程”的顺序，把每个环节的常见做法、选型考量、面试加分点都串起来。

一、概念速览

RAG 解决了什么问题

  • 减少幻觉：模型不再是”空想”，而是拿着资料回答问题
  • 引入私有知识：公司的技术文档、产品手册、客服知识库等
  • 知识可更新：换文档就行，不用重新训练模型

二、文档加载与分割（Chunking）

文档加载

用 DirectoryLoader 从本地目录加载文档：

为什么要对文档分块

LLM 有上下文窗口限制，同时 embedding 对长文本的语义表征效果会下降（虽然后续长上下文模型兴起后有人讨论”RAG 是否已死”，但 RAG 在效率、成本和可控性上仍然有不可替代的优势）。

分块策略：

策略 做法 适用场景
固定长度 + overlap 512 tokens，10% 重叠 通用，实现简单
语义分割 按句子/段落边界分 语义完整性好
递归字符分割 RecursiveCharacterTextSplitter 兼顾结构和语义

面试加分：chunk 大小是一个经典 tradeoff——太小则语义不完整，太大则检索不精准。overlap 的作用是防止信息在切分边界处断裂。

选型

以 Milvus 为例（向量数据库通过近似最近邻算法（如 HNSW）降低检索复杂度，从 O(N) 降到对数级。）

向量库选型对比

方案 优势 劣势
Milvus 分布式、高性能、功能全 部署重
Chroma 轻量、本地开发友好 生产级能力弱
pgvector 依托 PostgreSQL 有 PG 环境时方便
FAISS 纯本地、速度极快 不支持增量更新

五、查询优化：让检索更准

查询改写

直接拿用户原始 query 去检索，效果往往不好。查询改写的方法：

  1. LLM 重写：让模型把 query 改写成更清晰/完整的表达
  2. Multi-Query：生成多个不同问法，分别检索后聚合
  3. Step-Back Prompting：从具体问题”后退”到抽象问题：如”HNSW 参数含义” → “向量索引的工作原理”

稠密检索

六、混合检索（Hybrid Retrieval）

为什么需要混合检索

  • 稀疏检索（BM25）：基于词频、倒排索引，擅长精确关键词匹配
  • 稠密检索（Embedding）：基于语义向量，擅长近义词和语义理解

两者互补，结合使用效果更好。

融合方式

  1. Score Fusion：加权求和 final_score = α × BM25_score + β × embedding_score，归一化后再加权
  2. RRF（Reciprocal Rank Fusion）：对每个文档在两个检索结果中的排名取倒数融合

其中 k 是一个平滑常数（通常取 60）。RRF 的好处是不需要分数归一化，只依赖排名。

七、重排序（Rerank）

为什么需要 Rerank

向量检索返回 Top-K，但召回率高的代价是精度低。Rerank 用更强的模型（通常是用 Cross-Encoder）对 (query, document) 直接打分，精排出最相关的文档。

流程：

Rerank 本质上是 recall vs precision 的 tradeoff。检索阶段（召回）要广，Rerank 阶段（精排）要准。Cross-Encoder 虽然效果好，但要对每个 (query, doc) pair 做一次前向传播，成本高，所以只用在最后几步。

九、RAG 的关键作用

  1. 减少幻觉——模型不再”编造”知识
  2. 引入私有知识——公司内部文档、最新资料都能用
  3. 知识可更新——换知识库就行，无需重新训练
  4. 成本可控——相比微调，RAG 的维护和部署成本更低
  5. 可解释性——可以溯源到具体文档，答案是”有据可查”的

小结：RAG 各环节速查

环节 主要做法 常见坑点
文档分块 固定长度 + overlap / 语义分割 chunk 太大小/大，overlap 不够
Embedding BGE / text2vec 模型选型不适合语言/领域
向量存储 Milvus / Chroma / pgvector / FAISS 部署和增量更新策略
查询改写 LLM rewrite / Multi-Query / Step-Back 改写过度引入噪声
检索 稠密 / 稀疏(BM25) / 混合(RRF) 单种检索召回不全
Rerank Cross-Encoder 精排 计算成本高，不能对所有候选重排
Prompt 组装 强相关才用上下文 不相关文档会误导模型

RAG 的每一个环节都有 tradeoff 可以做文章——面试中能清晰地指出”为什么这么做”和”不这么做会怎样”，比背模板更有说服力。
RAG 更适合知识密集型任务，微调更适合行为/风格对齐。
